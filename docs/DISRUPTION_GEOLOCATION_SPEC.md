## 1 Approach in one paragraph

Put TfL's own localisation on the map first and read prose only where TfL gives none, and never draw a location that is not a slice of a real TfL route. One lazily-cached, single-flighted backend proxy route, `GET /api/disruptions`, fetches the date-window `/Line/{20 rail ids}/Status/{today−1}/to/{today+7}?detail=true` body (*measured D2/D3*: HTTP 200 with all 20 manifest ids **including tram**, 606,977 B raw / 23,293 B gz, 614–698 ms cold, 103 ms warm, `JSON.parse` 2 ms, heap delta ≈ 1 MB; *findings §2.6*: `affectedRoutes` 15/15, `affectedStops` 11/15 of the disrupted statuses in sample 13) once per 60 s for every viewer, runs it through the recorder's existing `compactStatus()` (`backend/src/status-recorder.ts:207-229`), and resolves each status in three tiers: **Tier 0** takes `isEntireRouteSection=false` slices and `affectedStops` (ordered NaPTAN ids, 103/103 present in the baked station files; *measured D2*: 48/48 partial routes in sample 13 and 10/10 in sample 01 are edge-by-edge baked branch edges) validated id-by-id and edge-by-edge against the baked branches; **Tier 1** is a keyword-anchored, line-scoped gazetteer + 18-rule template grammar whose station tokens must consume a whole capitalised run (no prefix shortening) and whose A→B pairs are resolved only as slices of TfL's own ordered route patterns (`orderedLineRoutes`, baked into `data/route-patterns/<line>.json` — a **hard P0 gate**, because *measured D1* the branch-fragment fallback draws 26 % fewer sections and chain-joined fragments draw phantom paths); Tier 1 runs in **shadow** on every non-Good status from day one and renders only after a production flag is flipped on a measured gate — with the flag off Tier 1 contributes **text only** (no rings, no endpoint points); **Tier 2** fails closed to line scope with the raw sentence. Whole-line closures (`Service Closed`, and `Planned Closure` with only entire-route sections — the 1,702-occurrence "Service will resume" and the six empty Overground `"<Name> Line:"` strings (×11 each, 66 occ) are *measured* all `Service Closed`) become a whole-line hatch, which is literally true and carries no attachment risk. The browser receives ids, severity classes, validity and the sentence (*measured D2*: 2,823 B items + 2,770 B notices + 423 B NR, brotli q4, busy weekend) and draws from the branch geometry it already holds (`frontend/src/realtime/trains-controller.ts:39-44`), with bands that are shape-coded (hatch / solid / dotted) and carry a line-coloured core stroke on the shared Circle/District/H&C/Met corridors. Station-facility notices (`/StopPoint/Mode/{rail}/Disruption`, 5.2 KB gz) ride the same response. Bus gets a **route-level** tier (whole learned polyline wash, default-off toggle, full reason text) ahead of National Rail, whose hub messages (already inside cached Darwin boards — zero new Darwin calls) are text in the hub's popup and a ring **only when the message names the hub itself**. Staleness is bounded server- and client-side at 10 min (*measured D3*: TfL's RealTime `toDate` is a rolling now+2–3 h stamp, so it can never be the un-draw signal). New TfL draw ≤ 1.2 req/min steady / ≤ 2.2 on a failing minute of the 60/min budget, independent of viewer count by construction (single-flight + failure back-off); resident RAM < 1 MB; the 607 KB body is parsed transiently (≈ 1 MB) and reported on `/health`.

### 2.2 Deliberately not built

- **No poller, no timers**: the route is a `registerProxyRoute` spec — cache-first, budget-gated, single-flighted, stale-on-failure with a max-stale bound, `x-cache` header, key redaction on non-200 (`proxy-route.ts:98-136`). A deployment nobody looks at makes zero calls. Nothing to close on SIGTERM (`server.ts:19-27` closes the app; the recorder is stopped at `app.ts:214`, timers `unref()`ed at `status-recorder.ts:353-355`).
- **No `backend/src/shared/` copy of the resolver**: resolution is backend-only. The one algorithm that must exist on both sides — the hop index over `branch.stops` consecutive pairs (`LineGraph` step (i), `sectionGeometry()` in the browser) — is declared as a mirrored pair in both file headers and pinned by one shared fixture (`fixtures/hop-index.json`) so divergence fails a test rather than a rider (§12 D3-9). Divergence fails closed anyway (the client drops a section with a missing hop).
- **No arbitrary graph search**: Tier 1 geometry is a slice of a real TfL route pattern (§5.4) or nothing. DFS/Dijkstra over fragments (`NrRailGraph.railPath`, `nr-inference.ts:195-240`) produces a path through Mornington Crescent for "Camden Town–Kennington via Bank" (*measured*), and **chain-joined fragments** do the same (12 stops vs 11 on real patterns, *measured D1* `probe-chains.txt`) — neither is used.
- **No branch-fragment fallback for Tier 1** (§12 D1-7), **no loop-union, no missing-conjunction rescue, no prefix-shortened station match, no straight-line geometry guess**.
- **No new Darwin calls, no bus stop-level geometry, no NR section resolution** (§7).
- **No prose-derived map mark before the gate**: with `DISRUPTIONS_PARSED_SECTIONS=0` the parser produces popup text and shadow-log lines only (§5.1-2).

## 5 Resolution algorithm

All of it runs in `backend/src/disruptions/*`, pure functions, once per cache miss.

### 5.1 Tier order (per `LineStatusEntry` with `s ∉ {10, 18}`)

1. **Tier 0 — structured.**
   a. `sections ← ar.filter(e === false)`; each `st` must have ≥ 2 ids, every id ∈ `stations(l)`, and every consecutive pair must be an edge of `LineGraph(l)`. Any failure drops **that route only** and logs `disruptions: bake-drift line=… ids=…`. No partial rescue: TfL's ordinals are contiguous on all partial sections in sample 13 (*measured D2*: 48/48 partial routes — the synthesized design's "34" was wrong; *findings §2.6* counts 46 = 8+16+4+4+14; the difference is a counting convention and is pinned by the fixture test), so a gap is a bake/feed mismatch. *Measured D3*: all partial routes lie inside their sentence's named section (district Earl's Court–Wimbledon, Edgware Road (Circle)–Earl's Court; elizabeth Ealing Broadway–Acton Main Line–Paddington; suffragette 11/3; weaver 13/11; windrush 7/5/5/7/3).
   b. Inbound/outbound copies with the same id set collapse to one section, `dir: b`; a one-direction slice keeps `i`/`o`.
   c. `affected ← as.filter(id ∈ stations(l))`. If `sections` is empty and `affected` non-empty: if the ids, ordered along a single route pattern, form a chain of graph edges → one section (`src: s`); otherwise `pts` with `role: affected`. An id in the station file but on no branch and no pattern can only ever be a `pts` entry (guard; none exist today — 676 = 676, *findings §4.1*).
   d. Whole-line promotion per §4 `wl`.
   e. Tier 0 succeeded when it produced ≥ 1 section, `wl`, or ≥ 1 affected point. Prose sections are then **discarded for rendering** (contradiction case: the Windrush Severe Delays status lists 8 entire routes under a sentence naming two closed sections, *findings §2.9[d]*), but the sentence is still parsed for `rest` (R10), `cause` (R11), `dir` (R8) — and for the shadow comparison (§5.6).
2. **Tier 1 — parsed.** Always runs (shadow). A clause is accepted only if every station token in every section clause of the line's primary sentences resolves (whole-run rule, §5.2-13) to exactly one co-located group on `l`, and the pattern rule (§5.4) returns a result. **Rendering**: only when Tier 0 gave no section/`wl`/affected point **and** `DISRUPTIONS_PARSED_SECTIONS=1`. With the flag off, accepted parsed sections are **not** emitted in any form — no `sec`, no `pts` — the item stays `sc: line, src: f` and the popup shows the sentence; the acceptance is visible only in the shadow log and `/health`. A clause that fails closed never emits its endpoints (the synthesized design's `pts role: end` is removed: R16's ring asserted a closure endpoint for a sentence the parser could not read — §12 D3-5).
3. **Tier 2 — fallback.** `sc: line`, `src: f`, `r` verbatim. Always reachable; never throws — any exception inside grammar or graph is caught per status, logged with line id + first 80 chars, and the item is emitted as Tier 2. The route never 500s because of a sentence.

Cause points (R11) are the one prose-derived mark allowed with the flag off, and only when the name resolves as a whole run on line `l`'s own gazetteer (an exact key, a hollow pin labelled "reported at"); the global-gazetteer fallback (49 token instances, *measured D1*) renders only with `pf = 1`.

Merging by `(l, canon(sentence))` happens after tiering.

### 5.2 Normalisation (`norm()`, identical for gazetteer names and notice tokens — one function, both sides)

1. Unicode NFC; HTML tags removed; entities decoded with a **generic decoder** — numeric `&#NNN;` / `&#xHH;` plus `&amp; &lt; &gt; &quot; &apos;` and `&nbsp;` (*measured D2*: only `&nbsp;` and `&amp;` observed in the 10 sampled Darwin messages, so a two-entry table cannot be refuted from data, but a missed entity would survive the client's `esc()` as literal text — a fixture with `&#39;` is pinned).
2. Curly quotes → straight; lower-case.
3. Apostrophes and backticks deleted: `Earl's Court` → `earls court` (corpus spelling `Earls Court` needs no alias).
4. `&` → ` and `.
5. `.` deleted: `King's Cross St. Pancras` → `kings cross st pancras`.
6. `-` and `_` → space, whitespace collapsed: `Harrow-on-the- Hill` (116 occ), `Harrow-on-the Hill`, `Harrow-on-the-Hill` → `harrow on the hill` (*measured D1*: resolves `940GZZLUHOH` exact after norm). `/` is **not** folded here: it never occurs in a baked name (*findings §4.3*) and is the fork separator (R6), handled before normalisation.
7. Trailing `-underground` dropped, then one trailing parenthetical group stripped **for a second key** only when the stripped form is unique on that line: `edgware road (circle line)` → also `edgware road`; `paddington (h&c line)-underground` → `paddington` — on the Circle this collides with `940GZZLUPAC` `Paddington`, legal under the co-located rule below; `kensington (olympia)` → `kensington olympia` (step 6) and additionally `kensington` because no other District station normalises to it. The builder logs every collision that is not co-located and keeps only the full key.
8. **Mode suffixes only**: ` tram stop` (all 39 tram names), ` underground station`, ` rail station`, ` dlr station` are removed. **Bare ` station` is never stripped** — Battersea Power Station (`940GZZBPSUST`, the only tube name ending in " Station", *measured D1* grep over `data/stations/*.json`) would otherwise key as `battersea power`, and the notice token `Battersea Power Station` then breaks R16 on "Station and Camden Town" (*measured D1*: 34 corpus occurrences lost — "Colindale and Battersea Power Station via Charing Cross" ×32, "Battersea Power Station and Camden Town via Charing Cross northbound only" ×2). Because notice tokens and gazetteer names go through the same `norm()`, the run "Battersea Power Station" and the key agree by construction (§12 D1-6).
9. `(london)` suffix and `london ` prefix on rail names give a second key only when the remainder is not itself another key on the same line (`london bridge`, `london fields` keep the full form only). **Elizabeth line exception**: `910GLIVST` "London Liverpool Street" gets no `liverpool street` second key under this rule because `910GLIVSTLL` already owns it — which is exactly what made the Shenfield case resolve to the wrong id (§12 D1-2). Co-location is therefore enumerated **by coordinates over all key forms including suppressed second keys** (rule 10), and `LIVST`+`LIVSTLL` form a group.
10. **Co-located groups (N-DUP)**: two ids on one line whose normalised bare names (any key form) are equal are legal only when they lie ≤ `COLOCATED_MAX_M = 300` m apart; the pair forms one group and either id satisfies a lookup. *Measured D1* (builder log with second keys included) over all 25 station files: **exactly four** pairs — circle Paddington (`940GZZLUPAH` H&C platforms / `940GZZLUPAC`, 255 m), elizabeth Paddington (`910GPADTLL` / `910GPADTON` "London Paddington", 82 m), mildmay Clapham Junction (`910GCLPHMJC` / `910GCLPHMJ1`, 5 m), **elizabeth Liverpool Street (`910GLIVSTLL` / `910GLIVST`, 52 m)**. Any other duplicate → collision → full key only. The synthesized design's "exactly three" and its **unverified** PAH/PAC distance are both closed by this measurement. Slicing treats a group as one node but the slicer remembers the **concrete** id each slice used (§5.4 step 2).
11. Hand alias table (line-scoped where stated; all from *findings §4.4*). **Aliases fire only on exact whole-run equality** (the run after norm equals the alias token) — never as a prefix of a longer run:

Typos: Damerau–Levenshtein ≤ 1 against the line's keys, only for whole runs ≥ 8 characters with exactly one candidate and not themselves an exact key anywhere (`west ruilsip` → `west ruislip`, `seven sister` → `seven sisters`, `heathrow terminal 2 and 3` → `heathrow terminals 2 and 3` — all *measured D1*; `bank` never rescues to `bark`).
13. **Whole-run rule (replaces "longest match ≤ 6 words")**: at an anchor the tokeniser takes the **maximal capitalised run** — consecutive raw whitespace tokens each of which (i) begins with an uppercase letter, a digit or `(`, or (ii) is `&`, or (iii) is a lowercase word such that the run-so-far plus this word (after norm) is still a prefix of some key or alias on line `l` (`Baker street`, `Wembley park`, `Heathrow Terminals 2 and 3`; `Highbury & Islington and Dalston` stops at `and` because `highbury and islington and` prefixes no key). The run stops at an anchor keyword, `,`, `/`, `.`, a mask, or any other lowercase word. The whole run (normalised) must equal a key, an alias, or a ≤ 1-typo rescue; **otherwise the token is unresolved (F1) — shorter prefixes are never tried**. *Measured D1* under prefix shortening: `Dalston Junction` → Dalston Kingsland on Mildmay (corpus ×14, drew Highbury & Islington → Dalston Kingsland, 3 stops, before R2's other-line clause), `Aldgate East` → Aldgate on Circle, `Edgware Road` → Edgware on Northern, `Harrow & Wealdstone` → Harrow-on-the-Hill on Met, `Shepherd's Bush Market` → Shepherd's Bush on Central, `Stratford International` → Stratford on Central, `West Hampstead Thameslink` → West Hampstead on Jubilee. ### 5.3 Template grammar (numbered; one real corpus sentence per rule)

Preprocessing, in this order: (1) split into sentences on `. `, `.\r\n`, `\r\n`, `! `, `? ` with `St.` protected and `. .` collapsed; (2) **apply the R12 masks** (dates/times → `<DATE>`/`<TIME>`, `(including Night Tube)`, `Bank Holiday`, `via any reasonable route`, severity phrases, remainder phrases, direction words); (3) classify each sentence (R1, R2) **on the masked text**; (4) within a PRIMARY sentence, whole-run lookup (§5.2-13) runs **only** at anchors — after `between`, `and` (inside an open between-clause), `to`, `from`, `via`, `at`, `towards`, `through`, the dash form ` - `, or a fork separator `/`. Unanchored names never match (R15). Ordering (2) before (3) is what rescues the dated closures the synthesized design lost (§12 D1-5).

| # | Rule | Corpus sentence | Result |

Given endpoint co-located groups `A*`, `B*`, optional `via` group `V*`:

1. **Per pattern, per direction** `d ∈ {outbound, inbound}`: for every pattern of direction `d`, for every index pair `(i, j)` with `ids[i] ∈ A*`, `ids[j] ∈ B*`, `i ≠ j`, take `slice = ids[min..max]`. Reject a slice whose **interior** contains any member of `A* ∪ B*` (twin rule). **Closest-pair rule (new, §12 D1-1)**: when a pattern lists an endpoint id more than once (the Circle ring branches carry Edgware Road (Circle Line) at index 0 and 27, Aldgate at 9/18, Victoria at 19/8 — *measured*), keep only the slice with the **smallest index distance** for that pattern and ordered pair; the wrap-around is never a candidate. *Measured D1* without it: "between Edgware Road and Paddington" and "Edgware Road and Baker Street" on the Circle drew the whole 27-stop ring, because the 2-stop slice and the 26-interior long-way slice are nested (no `A*∪B*` member in the long interior, so the twin rule alone does not fire) — a structurally certain wrong attachment on the real ring shape even though 0 corpus sentences match in 10 days. If `V*` is given, keep only slices containing a member. Each surviving slice records `(stopSet, concreteA, concreteB)`.
2. **Skip-stop nested collapse (replaces "keep the maximal set")**: two slices `S ⊂ T` of the same direction may collapse to `T` only when **(a)** they were cut at the **same concrete endpoint ids** (not merely the same groups), and **(b)** `S` is an order-preserving subsequence of `T` and every station in `T \ S` sits between two `T`-neighbours that are consecutive in `S` (i.e. `T` is an all-stations pattern and `S` a fast pattern skipping intermediate stops: Metropolitan Harrow-on-the-Hill–Aldgate 15 ⊃ 14 (Willesden Green), Wembley Park–Baker Street 4 ⊃ 3, *measured*). *Measured D1* counter-example that (a) blocks: Elizabeth `{910GLIVSTLL,910GLIVST}` → Shenfield gives a 15-stop slice through Whitechapel from `LIVSTLL` and a 14-stop direct slice from `LIVST` (chain Shenfield…Stratford→London Liverpool Street via branch 16/4, verified in `data/branches/elizabeth.json`); after group mapping 14 ⊂ 15, and the synthesized rule drew the Whitechapel tunnel for a Shenfield-metro closure. With (a) the two slices are non-nested → **fail closed** unless `via Whitechapel` / a via that only one contains disambiguates. Non-nested multiplicity → **fail closed** for that direction.
3. **Cross-direction decision (new, §12 D1-8)**: after per-direction collapse, compare the outbound and inbound results with the same rule: identical → one section `dir: b`; safely nested (step 2 a+b) → the superset, `dir: b`; interiors disjoint (the sets share only `A* ∪ B*` — a genuine one-way loop) → both, `dir: o` / `dir: i`; anything else → fail closed. One direction yields one set and the other none → emit the one. *Measured D1* without this step: Met Harrow-on-the-Hill → Aldgate was drawn **twice** per item (15 outbound + 14 inbound), likewise Baker Street → Harrow-on-the-Hill 7+6, Wembley Park → Aldgate 12+11, Piccadilly Acton Town → Heathrow Terminal 4 11+10 — the Met Harrow–Aldgate sentence alone is 624 corpus occurrences.
4. Prose directions (`eastbound`) are not mapped to inbound/outbound (rendering is undirected; the popup shows the word).
5. Structured sections never go through this rule; they are validated edge-by-edge (§5.1-a) and drawn as TfL listed them.

### 5.5 Fail-closed conditions (any one → the clause or route is not drawn)

- A station token's whole run has 0 candidates, or ≥ 2 candidates not in one co-located group, on line `l` after normalisation, exact-alias and the ≤ 1-typo rule (F1/F2). Shorter prefixes are never tried.
- A section clause has < 2 resolved endpoints (R16), or its `via` does not resolve on `l` (R7).
- §5.4 finds 0 slices, or > 1 slice not safely nested (step 2 a+b) in either direction, or the cross-direction comparison is neither identical, safely nested, nor interior-disjoint (F3–F5, F8).
- `A* = B*` (F6). A PRIMARY sentence with a section keyword that no rule consumes (F7).
- A structured `st` list has an id not on `l` or a consecutive pair that is not an edge (§5.1-a).
- The status has `s ∈ {10, 18}`; an empty `r` with no structured fields and `s ∉ closed-set` → `sc: line, k: info`.
- The only R1 prefix names a different line.
- Non-stations are absent from every gazetteer by construction.
- The route-pattern file is absent or failed validation for the line → no Tier 1 geometry for that line.
- The payload is older than `DISRUPTIONS_MAX_STALE_MS` → nothing is drawn (server serves no such body; client clears).
- Any exception → Tier 2 for that status, logged.

### 5.6 Shadow mode and the disagreement log

Tier 1 runs on every non-Good status even when Tier 0 succeeded. When both exist, the resolver compares stop **sets** (parsed vs structured, per item) and classifies `exact | subset | superset | disjoint | no-parse | no-oracle`; anything but `exact`/`no-oracle` logs one line `disruptions: parser <class> line=<id> skeleton=<masked> parsed=<n> structured=<n>` and bumps `disruptionsShadowDisagree`.
